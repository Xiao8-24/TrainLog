# 已批准新增功能 A、D · 0.7.0

用户于 2026-10-18 明确批准 A 和 D。每周计划/提醒（B）与 iCloud 同步（C）不在本轮范围。

## A：同一场手机与 Apple Watch 力量训练

在手机打开正在进行的逐组力量训练，先在手表打开 TrainLog，再点手机中的“连接这次力量训练”。连接会保存明确的训练与请求标识；手表确认后，由用户在手表主动开始。当前版本只连接手机力量草稿，不按日期或相似名称猜测合并历史记录，也不合并多个手表采集时段。

手机记录重量、次数、组数与备注；手表独立采集心率和系统活动能量。暂停与结束采集在手表操作，手机“完成”只完成手机记录。二者分别保留真实时长和区间；手表结束保存后，结果附加到同一条手机记录，不覆盖逐组内容。结果尚未送达时显示等待，原手表文件保留到手机事务提交并确认。

连接请求生效后，健康记录归手表管理，手机不额外导出一份。若尚未在手表开始，可从手表取消，或由手机发送取消并等待手表确认；取消已确认后才恢复手机健康导出。开始后不能切换回手机健康导出，以免重复。尚未开始但连接暂不可达时，不假设已经取消。

手机删掉关联训练，不会停止手表或删除 Apple 健康原件；删除收据阻止迟到结果恢复为第二条记录。若收到的标识找不到对应训练，也不猜测另建，保留接收文件并提示恢复原档案。手表意外退出后继续使用既有恢复机制；不能恢复的心率明细以健康原件为准。

V3 新增独立关联数据表，不改写 V1/V2 的实体定义或数据库位置。关联摘要与心率会随本机 JSON 备份保存；JSON 新导出版本3，继续读取1/2。CSV 保留原32列，再追加8列手表关联摘要；心率明细仅在 JSON 中。血氧和 VO₂ max 仍仅查询系统已有参考，不进入备份。

## D：交互小组件与快捷指令

桌面小组件使用原生 App Intent 按钮：继续指定草稿、打开日历；中号在休息期间提供结束休息，否则可打开模板入口。快捷指令提供继续训练、健身日历、按所选模板开始与结束当前组间休息。没有草稿时“继续”打开训练页面，不暗中新建；模板不存在时要求重新选择；已有草稿时继续原草稿。

操作要求本机身份验证，并通过系统打开 App 完成校验，不绕过锁屏或在后台自动开启手表健康采集。结束休息携带目标训练标识，只有仍与当前草稿匹配才生效；编辑器已打开时不会为此关闭未保存的表单。

扩展与快捷指令只读取 App Group 的最小摘要，增加模板标识/名称与休息截止，不读取数据库、心率、体重或备注。模板名称可能显示在系统快捷指令选择器中。首次、首次解锁前或 App Group 未配置时需先打开 App；主 App 与 Widget 必须使用相同 App Group 签名。

## 验证边界

协议、数据合并、幂等、旧草稿保护、迁移、备份及路由由自动化覆盖；真实 WatchConnectivity、健康权限、传感器、Siri、锁屏与系统小组件必须在签名配对设备复核。模拟器不支持真实 `transferUserInfo` 交付，不能据此声称跨设备已实测通过。

依据：[WatchConnectivity 数据传送](https://developer.apple.com/documentation/watchconnectivity/transferring-data-with-watch-connectivity)、[transferUserInfo](https://developer.apple.com/documentation/watchconnectivity/wcsession/transferuserinfo(_:))、[OpenURLIntent](https://developer.apple.com/documentation/appintents/openurlintent)、[本机身份验证](https://developer.apple.com/documentation/appintents/intentauthenticationpolicy)。
