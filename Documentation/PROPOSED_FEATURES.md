# 新增功能建议与审批

用户已于 2026-10-18 明确批准 **A 和 D**，进入实现与验证。**B、C 未批准，不开发。** 没有启用云端同步或计划提醒。

| 编号 | 建议 | 为什么值得增加 | 成本与需要确认的边界 |
|---|---|---|---|
| A（优先） | 手机逐组记录与 Watch 传感器合并为同一场训练 | 当前需要选择一个记录入口。合并后可在手机记重量/次数，同时保留 Watch 心率与系统能量，避免两条记录重复计数 | 高：需要跨设备统一标识、控制权、断连恢复与结束冲突；必须配对真机验收。旧记录不会自动猜测合并 |
| B | 每周训练安排与可选本地提醒 | 模板已有动作配置，但还没有“哪天练什么”；提前安排能减少开始训练前的操作 | 中：先做用户手动安排、模板关联、跳过/改期。提醒另行主动授权，不自动生成或强制调整计划 |
| C | 可选 iCloud 训练档案同步 | 换手机、多设备使用时不必完全依赖手工 JSON 备份 | 高：需要 CloudKit 签名能力、迁移、离线冲突和删除传播设计；明确哪些训练/身体数据进入云端，并保留纯本地模式 |
| D | 交互小组件与快捷指令 | 从桌面继续草稿、打开指定模板、控制已有休息计时，减少训练中寻找入口的次数 | 中：先限定明确且可撤销的操作；不允许后台擅自开始 Watch 健康训练，过期草稿与锁定状态需处理 |

本轮按批准实现 A、D。B、C 继续等待后续独立审批；C 涉及数据架构与云端隐私，不随本轮一并开启。

本轮不建议增加自动“恢复评分”、医学风险判断或由单次心率推算 VO₂ max：现有输入不足以支持可靠结论。继续使用系统已有测量和有出处的训练统计。
